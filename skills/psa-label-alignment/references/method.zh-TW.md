# 方法說明：標籤字距比對

這份文件說明 `scripts/psa_label_check.py` 的演算法。

## 1. 把標籤拉正

- 用 HSV 色彩空間找出標籤的紅色外框。
- 候選的紅色四邊形拉正後，內部至少要有 35% 是又亮又不飽和的白色標籤底，才算數。這樣可以排除形狀剛好像標籤的橘色木桌或紅色桌墊。
- 找到最大的紅色四邊形後，把四個角透視轉換成 960 × 291 px 的標準標籤。PSA 官方圖和賣家照片都做一樣的處理。
- 如果自動偵測失敗，可以手動指定四個角。

## 2. 逐字量位移

- 把 PSA 官方標籤二值化，排除紅框、條碼和 PSA 全像標誌三個區域。
- 剩下的每一個連通區塊就是一個字或數字。
- 用正規化互相關（NCC）在賣家照片的標籤裡，±30px 範圍內找出每個字的位置，再用拋物線擬合做到次像素精度。
- 得到每個字的位移 (dx, dy)。

## 3. 去除整體變形

- 用所有字的配對結果擬合一個 RANSAC 單應性矩陣（homography）。
- 這一步可以消除拍攝角度和紅框角點偵測的誤差，做完後再重新量一次每個字的位移。
- 單應性變換是平滑的，不可能讓相鄰兩行往相反方向偏，所以如果標籤是重新排版的，差異在這一步之後仍然會留著。

## 4. 評分

1. 依 y 座標把字分成行。
2. 每一行的 dx 曲線先做 3 點中位數平滑，行頭行尾也一樣。這樣單一個字被配到隔壁相同字母（例如 "EEVEE"）時，不會左右結果；真正重新排版的話，會是一整串字一起偏。
3. 相鄰兩行在共同的 x 範圍內內插比較，取差距的最大值。
4. 用所有相鄰兩行中最大的差距來判讀：
   - **≤ 4px**：一致（`CONSISTENT`）。
   - **≥ 8px**：不符（`MISMATCH`）。
   - **介於兩者之間**：無法判斷（`INCONCLUSIVE`）。
   - 比對到的字少於 40 個，或相關係數中位數低於 0.70，也判為無法判斷。

## 5. 用別張證書、別的等級當參考（`--description-only`）

參考圖不一定要是同一張證書。加上 `--description-only` 時：

- 拿掉最下面的鑑定編號那一行；
- 每一行在 x = 300 右邊第一個超過 70px 的空隙處切開，右邊那一欄（卡號、等級如 "GEM MT 10" 或 "MINT 9"、鑑定編號）不比對。

剩下的是左邊的說明文字，同一張卡在同一個時期，PSA 都用同一份排版印。

## 6. 多張參考圖投票

`--ref` 可以給很多張，每張分別比對：

- 只要跟**任何一張**可用的參考圖一致，就是一致（`CONSISTENT`）；
- 跟**全部**都不符（至少兩張可用，或只給一張時），才是不符（`MISMATCH`）；
- 其他情況是無法判斷（`INCONCLUSIVE`）。

用「任何一張」而不是「多數決」，是因為 PSA 會在不同時期重新排版同一張卡的標籤。例如金澤皮卡丘，6000 萬到 6300 萬號左右的證書印成 "S – P"（有空格），7700 萬號以後印成 "S-P"。葉伊布 VMAX（S6a 089/069）也一樣：6300 萬到 6600 萬號左右印成 "HEROES – HYPER"，8300 萬號以後印成 "HEROES-HYPER"。一張 6300 萬號的真品，跟一張舊版參考圖的差距是 0.30px，跟六張新版參考圖差了 18–25px。真品可能跟另一個時期的真品參考圖不一致，但重新排版的假標籤應該跟全部都不一致。預設抓 8 張，通常兩個時期都涵蓋得到，就算有幾張照片不能用（貼紙蓋住標籤、反光、找不到紅框）也還夠。

## 校準數據

單位是像素，標籤寬度 960px。

| 比較 | 相鄰兩行最大差距 | 結果 |
|---|---|---|
| PSA 官方圖跟自己比 | 0.03 | 一致 |
| 真品照片（161870798）vs 該證書的 PSA 官方圖 | **0.34** | 一致 |
| 真品照片 vs **另一張證書**的 PSA 官方圖（`--ignore-cert-line`） | 0.21 | 一致 |
| 兩張不同證書的 PSA 官方圖（只比前三行） | 0.86 | 一致 |
| 可疑照片（134699919）vs 該證書的 PSA 官方圖 | **30.75** | 不符 |
| 可疑照片 vs 另一張證書的 PSA 官方圖（`--ignore-cert-line`） | 34.71 | 不符 |
| 真品照片（161870798）vs 3 張 SNKRDUNK PSA10 照片（`--description-only`） | 0.24（3/3 一致） | 一致 |
| 可疑照片（134699919）vs 同樣 3 張 SNKRDUNK 照片（`--description-only`） | 22.06（0/3 一致） | 不符 |
| 真品 PSA9 葉伊布 VMAX（153427845）vs 3 張 SNKRDUNK PSA9 + 1 張 PSA10（`--description-only`） | 0.19（4/4 一致） | 一致 |
| 同上，但用 PSA10 參考圖且**不加** `--description-only` | 27–31 | 不符（等級那一欄不同） |

同一張卡、同一個時期的不同證書，前三行說明文字的排版完全相同，差距在 1px 以內。所以查不到該證書頁面的時候，可以改用同款卡其他證書的照片當參考。不同時期的排版可能不同（見第 6 節），所以要用多張參考圖。

**注意：** 目前的閾值只用幾張真品和一張假品校準，是暫定的。歡迎在 `examples/` 加入更多已知真假的案例。

## 取得圖片

- **SNKRDUNK（預設的參考圖來源）：** `scripts/snkrdunk_refs.py` 會自動處理。
  - 搜尋：`https://snkrdunk.com/search?keywords=<關鍵字>`，HTML 是伺服器端產生的，裡面有 `/apparels/<id>` 連結。用卡號（例如 `144 s-p`、`089/069`）搜尋比用卡名準。
  - 某張卡的所有出品：`https://snkrdunk.com/v1/apparels/<id>/used?page=<n>&perPage=50`（JSON）。看 `displayShortConditionTitle`（`PSA10`、`PSA9`…）、`status`/`statusText` 和 `primaryPhoto.imageUrl`（正面照）。
  - 已經過 SNKRDUNK 鑑定的狀態：4 取引完了、11 運営の発送待ち、13 到着待ち，優先使用。狀態 0 是還在出品中、尚未鑑定。
- **PSA 官網：** `https://www.psacard.com/cert/<鑑定編號>`。網站常會用機器人驗證擋住自動化瀏覽器，這時請使用者自己下載或截圖。
- **Mercari：** `https://static.mercdn.net/item/detail/orig/photos/<商品ID>_<第幾張>.jpg`。
- **Rakuma：** 商品頁 `img` 標籤裡的 `https://img.fril.jp/img/<a>/l/<b>.jpg`。
- **沙盒連不到圖片網站時：** 用瀏覽器打開圖片，透過 canvas 匯出成 base64 再解碼。詳細步驟見英文版 method.md。
- 一定要用賣家上傳的**原圖**，不要用商品頁的截圖，截圖會被縮小。

## 搭配的其他檢查

- **賣家的照片是不是就是 PSA 官方圖：** 官方圖是灰色背景、正面、沒有反光。如果賣家只放官方圖，等於什麼都沒證明。
- **背面 QR code：** QR code 有效只是必要條件，假卡殼也會直接複製真的 QR code。
- **卡片在殼裡的位置：** 跟 PSA 官方圖相比，如果偏了大約 1–2mm，可能是不同的卡殼，或卡被換過。
- **價格和賣家：**
  - 價格只有行情的兩到三成，或 PSA10 用 PSA9 的價格賣。
  - 很多張不同的 PSA10 都標同一個價格。
  - 賣家 0 評價、沒有做身分驗證、剛上架幾小時。
  - 商品分類亂填，用來避開卡片類的審查和鑑定服務。
- **到貨後的實體檢查：**
  - 背光透視：真品可以隱約透出標籤的字。
  - 全像貼紙要有變色效果。
  - 卡殼側面接縫要整齊，沒有撬開的痕跡。
